# Classify a New File

Before creating a file, identify its responsibility, runtime, owning feature, and consumers. Choose the narrowest existing owner. Do not introduce a new shared category merely because two files look similar.

## Placement

- `src/app`: Next.js routes, layouts, route handlers, error boundaries (`error.tsx`), and global styles. `page.tsx` performs the server-side data calls and passes results to its screen via props. Keep it thin: route inputs, one fetch, render the screen.
- `src/screens/<feature>/<feature>-screen`: The complete page-level screen — the folder's `index.tsx` is the screen itself, a client component that orchestrates the page's logic.
- `src/screens/<feature>/<feature>-screen/<component>`: One-off and non-shadcn components orchestrated by that screen, each in its own folder.
- `src/components/<name>`: Shared components used across features — header, footer, sidebar, and similar chrome — placed directly under `src/components` with no extra grouping folders.
- `src/components/ui`: Shadcn-managed primitives. Preserve the layout generated by shadcn.
- `src/server/<feature>/api.ts`: Server-only reads and server application logic.
- `src/server/<feature>/actions.ts`: Mutations intentionally exposed as Server Actions.
- `src/lib`: Third-party initialization, adapters, shared types, and utilities. Not client-only — browser orchestration lives here when colocated with its adapter (e.g. `src/lib/firebase/admin-auth.tsx`).
- `src/proxy.ts`: Lightweight request redirects.

## Folders and Entry Points

Every screen and component is a folder whose `index.tsx` is the implementation itself. Never create an `index.ts` just to re-export a sibling file, and never import a `.tsx` file directly — import the folder.

- File and folder names are kebab-case (`stat-card/`, `search-form/`); `index.tsx` is the only entry name.
- The screen lives at `<feature>-screen/index.tsx` and is the main orchestration.
- One-off components for that screen live beside it in their own folders.
- Shared components live directly under `src/components/<name>/index.tsx`.

```text
src/screens/dashboard/dashboard-screen/
├── index.tsx            # "use client"; the screen itself
└── stat-card/
    └── index.tsx        # one-off component for this screen

src/components/header/
└── index.tsx            # shared chrome component
```

## Runtime Boundaries

- `page.tsx` awaits its feature's server API and hands data to the screen as props.
- Screens are `"use client"` components: they orchestrate logic and compose child components but hold no database or backend implementation.
- Components receive data through props.
- Server modules and server-side library adapters use `import "server-only"`.
- Browser adapters and providers use `"use client"` only when browser APIs, state, or event handlers require it.
- Reach for `src/app/api` only when a client needs a raw HTTP endpoint a Server Action cannot serve; the Firebase ID-token to session-cookie exchange lives in `src/server/auth/actions.ts`.

Before finishing, confirm imports use the folder entry point and no obsolete shared file or empty folder remains.
